## Протокол встречи
В ходе встречи были рассмотрены следующие вопросы и приняты решения:
- **Итоги второй итерации**
  - Команда подтвердила завершение следующих задач:
  - Реализован полноценный CRUD курсов с интерфейсом управления.
  - Подключена реальная база данных с миграциями.
  - Настроено Docker-окружение для разработки.
  - Настроен CI (GitHub Actions) с проверкой линтера, типов и сборки.

- **Бэкенд (Никита, Полина)**:
  - Разработать endpoint для создания команд, приглашения участников, выхода из команды.
  - Реализовать назначение команд на проекты:
  - Ручное назначение – преподаватель выбирает команду и проект (после уточнения с заказчиком, возможно, будет разрешено или запрещено).
  - Автоматическое назначение – по дедлайну или алгоритму.
  - Добавить возможность преподавателю блокировать проект (если проект уже занят или по иным причинам) – вопрос вынести на уточнение заказчику.
- **Фронтенд (Катя)**:
  - Страница управления командами: студент видит свою команду, может создавать команду, приглашать участников, принимать приглашения.
  - Преподаватель видит все команды по курсу.
  - Интерфейс для обмена проектами между командами (кнопка, подтверждение преподавателем).
- **Визуализация распределения**:
  - Оставить как в макетах (таблица с командами и проектами). В случае замечаний можно будет скорректировать.
- **Вопросы, требующие уточнения у заказчика**
  - Может ли преподаватель вручную назначать команду на проект?
  - Нужна ли кнопка блокировки проекта преподавателем?
  - Как будет реализована авторизация студентов (LDAP, тестовые данные)?
  - Каким должен быть формат CSV для импорта данных (создавать тестовый файл самим или ожидать образец от заказчика)?
